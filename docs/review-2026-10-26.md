## Should-fix

### S1. ✅ Fixed. The smoke privacy check passes vacuously on a local run
- **Problem:** `shouldCount()` never counts `127.0.0.1` (`site/js/stats.js:7`), so a local smoke run intercepts 0 beacons and still prints ✓ (`scripts/smoke.mjs:357`). The leak regex also hard-codes five party ids (`scripts/smoke.mjs:124`). The check is only meaningful against a deployed URL, which the README now states.
- **Fix:**
  - Fail when a `baseUrl` was given and 0 beacons were seen.
  - For local runs, inject a flag that also allows private hosts.
  - Build the leak regex from all ids in `parties.json`.

### S2. → Post-election work. Coalition state reaches the host (Netlify) in the request URL
- **Problem:** state lives in the query string (`site/js/compat.js:277-298`). Opening a shared link sends `?m=…` to Netlify in the request line, and in the same-origin `Referer` of the `data/*.json`, CSS and JS requests. It never reaches a third party: the beacon sends the path only, and `Referrer-Policy: strict-origin-when-cross-origin` trims outbound links to the origin. Netlify's own HUD script (`/.netlify/scripts/hud`) makes no network requests; its links go to app.netlify.com only on click.
- **Why not critical:** it goes only to the first-party host and was a deliberate design choice. Moving it is a routing change, too risky the day before the election.
- **Fix (after the election):** move the state into the fragment, for example `#results?m=…`, which browsers never send. The README's privacy paragraph now describes the current behavior accurately.

### S3. A base that is also outside support loses "outside" on share or reload
- **Repro:** choose ש״ס as base in results, go back, toggle ש״ס "מבחוץ". The URL stays `?b=shas&m=likud,utj`, because `serializeState` drops the base from `o` (`site/js/compat.js:294`) and `parseState` filters it out (`:283`). The shared link then shows a different inside/outside seat split.
- **Fix:** keep the base in `o` when it is outside, and stop filtering `b` out of `o` in `parseState`. Add a round-trip test.

### S4. ✅ Fixed. The sheet dialog has no accessible name
- **Problem:** `<dialog id="sheet">` (`site/index.html:58`, filled at `site/js/app.js:565-572`) has no `aria-labelledby`, so screen readers announce just "dialog".
- **Fix:** give each sheet's `<h2>` an id and set `aria-labelledby` on the dialog in `openSheet`.

### S5. Picking a party in the party sheet's "השוו עם…" select drops keyboard focus
- **Problem:** the `change` handler (`site/js/app.js:747-750`) calls `partySheet`, which replaces the whole dialog's `innerHTML` (`:628-640`). Focus is lost inside a modal.
- **Fix:** after re-rendering, focus the new `select[data-act="compare"]`, or re-render only the content below it.

### S6. ✅ Fixed. Share button on empty and single-party results
- **Problem:** the results bar always renders "שתפו" (`site/js/app.js:446-448`). With 0 parties, the share text is "הקואליציה שבניתי:  · 0 נושאים בסתירה חזיתית".
- **Fix:** render it only when `members.length >= 2`.

### S7. The live-region message after removing a party implies it is still in
- **Problem:** `setState(…, { announceParty })` (`site/js/app.js:38-41`) always announces `S.results.live(name, n)` ("<party>: N נושאים בסתירה חזיתית בקואליציה"), also after that party was removed (toggle off, friction removal).
- **Fix:** use separate "added" and "removed" strings.

### S8. `import-csv` diffs against the research file, not the live data
- **Problem:** `scripts/import-csv.mjs:63` uses `research/merged.json` when it exists. After the first import, the printed diff shows changes that are already live and can hide real ones.
- **Fix:** diff against `site/data/positions.json`.

## Checked and fine
- **Escaping:** all dynamic HTML goes through `esc()`. Source URLs are validated as http(s) by `validate.mjs`.
- **URL params:** unknown, duplicate, empty and repeated params are handled. `?b=zzz,likud&m=likud,likud,,LIKUD&o=raam&o=shas` parses to base ליכוד, members ליכוד + רע״ם, outside רע״ם.
- **Coalition sizes:** empty and single-party results render without errors. The single-party view shows that party's profile and no seat numbers.
- **Linked parties:** adding one adds the other once. Each can be removed. The linked note shows when either is selected. Presets include both.
- **Outside support:** counted in the seat split and in compatibility, as the method page says. Presets set it correctly.
- **Analytics beacon:** sends only path, title, screen width, referrer origin and a cache-buster. Verified by unit tests and on production.
- **Layout:** no horizontal overflow at 390px or 1280px. The host badge doesn't cover the poll sentence or the bar button (smoke).
- **Size:** about 56 KB gzipped for the page, code and all data (og.png not counted).

## Post-election work
- **Fragment routing (S2).** Move the coalition state from the query string into the fragment, for example `#results?m=…`, so it never reaches the host. Requirements:
  - Old `?m=` links must keep working: read them once, then rewrite them to the fragment with `replaceState`.
  - Hash routing (`#build` / `#results` / `#method` / `#why`) must coexist with the new state format.
  - The share URLs and the smoke privacy checks need updating.
- **Full Content-Security-Policy.** Today only `frame-ancestors 'none'` is set, together with `X-Frame-Options: DENY` and a `Permissions-Policy`. A full policy should be roughly `default-src 'self'; connect-src 'self' https://miimmi.goatcounter.com; img-src 'self' https://miimmi.goatcounter.com data:; frame-src 'self'`. Test it against Netlify's injected HUD script, which builds a `srcdoc` iframe with an inline script, and against the beacon's `sendBeacon` and `Image` fallback.
- The remaining should-fix items (S3, S5, S7, S8) and the nice-to-have cleanup, especially the dead CSS and strings.
