### L1-1. The 🚩 red-line evidence never reaches the site
- **Lens:** data and neutrality. **Status:** CONFIRMED. **Effort:** M.
- **Where:** `site/data/positions.json:138, 160, 182, 292, 798`, rendered by `evidenceHtml` at `site/js/app.js:635-640`. Validate: `scripts/lib.mjs:340-341`.

### L5-2. A 5-minute cache on everything can mix old and new files after a deploy
- **Lens:** performance. **Status:** PLAUSIBLE. **Effort:** S.
- **Where:** `netlify.toml:6` (`Cache-Control = "public, max-age=300"` for `/*`).
- **Problem:** for up to 5 minutes after a deploy, a returning browser can combine a fresh `app.js` with a cached `strings.js` or JSON file. A renamed key then means a TypeError and the load-error message. There were 11 to 37 commits a day since 4.11. ETag revalidation works: `If-None-Match` gives a 304 with 0 bytes.
- **To confirm:** deploy a renamed string key to a draft while an old tab's cache is warm.
- **Fix:** add per-path rules, which need no build: `max-age=0, must-revalidate` for `/`, `/en/*`, `/js/*`, `/css/*` and `/data/*`, and a long max-age for `og*.png` and `favicon.svg`. Immutable caching would need hashed filenames, which the no-build rule rules out, and hand-written `?v=` specifiers are too brittle.

## Feature ideas

Each idea was tested against the neutrality rules: mechanical, sourced, no ranking, no filtering by outcome, no default coalition.

1. **The actual government as a sourced scenario.** Once the government is sworn in, add it to `scenarios.json` with its members, supporters and abstainers, the Knesset vote record as the source, and the date. Visitors can then compare the real coalition's clashes with the ones the media scenarios implied.
   - **Rules:** it must stay one scenario among the others, alphabetical, never the default view ("no default coalition").
   - **Value:** high, the natural next chapter. **Effort:** S.
2. **The coalition guidelines (קווי היסוד) against the members' positions.** Place the signed guidelines on each topic's axis with the same source rules as a party (quote, date, archive), and show each member's distance from them.
   - **Rules:** a placement is a judgment, so it needs the same "no source, no position" rule and the same review. Party positions stay "as of election eve". The guidelines are a separate, dated layer and never move a party's cell.
   - **Value:** high. **Effort:** L.
3. **Two coalitions side by side.** Put two member sets in one fragment, e.g. `#compare?m=…&m2=…`, and show the per-topic status for each.
   - **Rules:** mechanical, but both sets must appear in a fixed order (the order typed), with no "better" column. State stays in the fragment.
   - **Value:** medium. **Effort:** M.
4. **Versioned data snapshots.** Name each download by its changelog entry (e.g. `positions-2026-11-08.csv`) and keep older versions, so researchers can cite a fixed version.
   - **Rules:** none touched.
   - **Value:** medium, and it fits the portfolio. **Effort:** S.
5. **A share image of the results summary.** Draw the summary to a `<canvas>` client-side and pass it to `navigator.share({files})`.
   - **Rules:** it touches the CSP. A blob preview needs `img-src blob:`, a new source in the policy. Sharing the file without previewing it needs no CSP change. The image must carry the CEC source line before any seat number (smoke rule) and no ranking wording.
   - **Value:** medium. **Effort:** M.
